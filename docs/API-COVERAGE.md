# Module API coverage

This document lists which module API functions in the vendored
`src/include/redismodule.h` the SDK wraps, and ranks the missing ones by
evidence of need (#90). The [per-API table](#per-api-table) at the end is
generated by `.github/scripts/api-coverage.py`; the other sections are written
by hand. A missing API alone is not a reason to add a wrapper: implementation
issues are filed only for gaps with a concrete consumer.

## Method

The script reads every `REDISMODULE_API ... (*RedisModule_X)(...)` declaration
in the header. It skips the five long-double declarations that the header has
commented out, which have no binding. The count of 404 in #90 included those
five; since #106 added five others (three subkey notification APIs,
`AddPostNotificationJobForKey` and `GetClusterNodeSlotRanges`), the header
again declares 404, none of them commented out.
It then tokenizes the Rust sources under `src/`, except the generated bindings
in `src/redisraw/`, drops comments and string literals, and records each
`RedisModule_X` name with the function, method or `macro_rules!` definition
that contains it. The SDK obtains an API through
`__required_api!(RedisModule_X)`, `__available_api!(RedisModule_X)`, the
`api!` proc macro, or the raw `Option` pointer, often inside `pub(crate)`
helpers in `src/raw.rs`.

Whether safe code can reach a reference is decided on a call graph built by
name, searched from the public items: `pub` functions of public or re-exported
modules, `pub` methods and trait implementations of types that are not
private, exported macros that are not `#[doc(hidden)]`, and the SDK paths the
proc macros in `redismodule-rs-macros` generate. A function nested in another
item, or emitted by a macro, is reached through it. Without type information,
a method call matches the methods of that name on types its file names, and a
bare call matches free functions in scope. The result is approximate: a name
collision can add a path, and `cfg` attributes other than `test` are ignored,
so an API reached only at some compatibility floors counts at all of them.
Tests do not count. The script's `OVERRIDES` table holds the classifications
checked by hand, each with its reason; the generated section lists them.

### Status

- **safe**: a public item that is not `unsafe` reaches the API: a function, a
  method, a trait implementation such as `Drop`, or a macro.
- **unsafe**: only `unsafe` public items reach it, such as the `pub unsafe fn`
  helpers in `raw`, `alloc` and `event_loop`.
- **internal**: the SDK calls it, but only in plumbing it drives itself or as a
  check inside another wrapper. No public item exposes what the API does.
- **none**: no SDK code refers to it.

`unsafe` code can call every API through the raw bindings:
`redis_module::raw::RedisModule_X` is an `Option` of an `unsafe extern "C"`
function. Status none means the SDK adds nothing to that. Most data-type
operations are also available as commands through `RuntimeContext::call`.

### Columns

- **introduced**: the first Redis minor version, among the sources examined,
  whose `module.c` registers the API with `REGISTER_API` or defines `RM_X`.
  The sources are one patch release of each line, the ones CI pins where it
  pins one, so an API added in a patch release shows under its minor version,
  and 6.0 means 6.0.20 or earlier.
  Enterprise marks the header's "bigredis extensions"; not in OSS marks an API
  that no examined source defines.
- **floor**: the lowest `min-redis-compatibility-version-*` floor in
  `Cargo.toml` at or above the introduced version, or none. See
  [COMPATIBILITY-FLOORS.md](COMPATIBILITY-FLOORS.md). A floor is a compile-time
  assumption; the server may still lack the API.
- **access**: how the SDK obtains the pointer. `required` is
  `__required_api!`, which panics when the API is missing; `available` is
  `__available_api!`, which returns an error; `api!` returns an error below the
  API's floor and requires it at or above; `direct` reads the `Option` itself,
  checked or expected by hand.
- **reached through**: for safe and unsafe APIs, the nearest public entry
  points; for internal ones, the referencing items, except that a
  hand-classified row keeps the automatic analysis's nearest public entry
  points. At most two are shown.
- **fit**: for an API that is not safe, the context view a wrapper would extend
  in the SDK's capability model (see
  [MIGRATING-3.0.md](MIGRATING-3.0.md#events-and-locked-workers-have-separate-context-views)),
  then any equivalent the SDK already offers.
- **requests**: upstream issues and pull requests that ask for the API, and
  this repository's issues.

The fit values:

| fit | where a wrapper would live |
|---|---|
| registration | `RegistrationContext`, during module load |
| command | `Context`, in a client command or a blocked client's reply or timeout callback |
| event | `EventContext`, for module-owned callbacks, timers and subscriptions |
| runtime | `RuntimeContext`, which every locked view dereferences to |
| key | `RedisKey` or `RedisKeyWritable`, which borrow a runtime view |
| worker | `ThreadSafeContext` and `DetachedContext` and their lock guards |
| blocked client | the `BlockedClient` handle |
| callback (...) | the native callback that receives the API's handle, such as a data type's I/O or digest, defragmentation, or a command filter |
| context-free | the API takes no context; a free function, like `redis_module::milliseconds` |
| n/a | no wrapper is expected |

### Regenerating

```sh
python3 .github/scripts/api-coverage.py --redis-src <dir>
python3 .github/scripts/api-coverage.py
python3 .github/scripts/api-coverage.py --check
```

`<dir>` holds Redis `src/module.c` files renamed `module-<version>.c`, such as
`module-8.10.2.c`. Without `--redis-src`, the script reuses the introduced
versions, the list of sources and the undeclared APIs recorded in the
generated section, so regenerating needs no Redis checkout. `--check`
regenerates the section the same way, writes nothing, and exits non-zero if it
differs from the committed text: after a change to the header, the SDK
sources, the floors in `Cargo.toml` or the script's tables. It also fails
while an API has no recorded version, as a newly declared one does until the
script runs with `--redis-src`. `--report` prints each API's automatic and
final status. The script uses the Python 3 standard library only.

The vendored header marks no API experimental. `build.rs` still defines
`REDISMODULE_EXPERIMENTAL_API`, which nothing in the header tests.

## Ranking by evidence of need

Evidence, strongest first:

1. The downstream module of #89 calls the API through raw bindings, and the
   SDK has no safe equivalent, so the port would keep that raw code.
2. An upstream pull request opened from a module organization's fork.
3. Another upstream issue or pull request, or a design issue here.
4. No request found: not ranked.

Within a tier, gaps with more separate requesters rank higher, then more recent
requests. Tier 2 is one requester's series, ranked in its own order: upstream
PRs 442 and 444 build on the command filters of upstream PR 437.

## Downstream module (#89)

#89 ports [redis-developer/redis-event-stream-module](https://github.com/redis-developer/redis-event-stream-module).
This section surveys its module sources, `src/` and `examples/notifytest.rs`,
at `0cb93ba`, the `main` revision #89 records, which depends on upstream
`redis-module` 2.1.3. It is not a port: the list is what the sources call, not
what the port turns out to need. Their other SDK use goes
through wrappers this SDK still has: logging, `call` and `call_ext`,
`get_flags`, `get_redis_version`, `add_post_notification_job`, configuration
registration, the INFO builder, `ThreadSafeContext` and `RedisAlloc`.

API pointers the downstream calls through `redis_module::raw`:

| API | downstream use | in this SDK |
|---|---|---|
| `AddACLCategory`, `GetCommand`, `SetCommandACLCategories` | `src/lib.rs` adds the `eventstream` ACL category and tags three commands with it, accepting the error a reload returns for an existing category | safe: `redis_module!`'s `acl_categories` accepts the `EBUSY` Redis returns for a category kept from an earlier load |
| `AddPostNotificationJob` | `src/lib.rs` refuses to load without it | safe: `EventContext::add_post_notification_job` |
| `SubscribeToKeyspaceEvents` | `src/lib.rs` subscribes with a mask chosen at load, through a raw callback that accepts non-UTF-8 event names | safe: `EventContext::subscribe_to_keyspace_events`; event names are decoded lossily |
| `SubscribeToServerEvent` | `src/lib.rs` subscribes to the flush and SWAPDB events, whose data the old SDK did not deliver, to the configuration event, and to the cron event only when checkpointing is configured | safe: `#[flush_info_event_handler]`, `#[swapdb_event_handler]`, `#[config_changed_event_handler]` and `#[cron_event_handler]`. `EventContext::subscribe_to_server_event(ServerEventHandler)` also supports conditional static subscriptions at runtime while preserving attribute handlers (#114). |
| `GetSelectedDb`, `SelectDb` | `src/capture.rs`, `src/commands.rs`, `src/config.rs` and `src/markers.rs` write to database 0 and restore the selection | safe: `RuntimeContext::get_selected_db`, `select_db` and `with_db` |
| `Milliseconds` | `src/capture.rs` reads the server clock for stream trimming | safe: `redis_module::milliseconds` |
| `GetThreadSafeContext`, `ThreadSafeContextUnlock`, `FreeThreadSafeContext` | `src/dispatch.rs` creates the writer thread's context and releases it | safe: `ThreadSafeContext` and its guard |
| `ThreadSafeContextTryLock` | `src/dispatch.rs` locks without blocking in the experimental asynchronous write modes, so unload cannot deadlock | safe: `ThreadSafeContext::try_lock` and `DetachedContext::try_lock` (#113) |
| `GetRandomHexChars` | `src/markers.rs` makes the generation id | none |
| `ClusterCanonicalKeyNameInSlot` | `src/cluster.rs` picks a hash tag per slot on 7.4 and later | none; `cluster::key_for_slot` is a substitute that generates different names (rank 2) |

Two of these are gaps. The port can keep raw calls for them, so none blocks
it; they are what #89 would record as remaining raw-API workarounds.

## Gaps by area

Areas the generated table shows as fully safe are left out. "Fit" refers to
the values above.

### Memory

`RedisAlloc` allocates with `Alloc` and frees with `Free`. `Realloc`, `Calloc`,
`Strdup` and the `Try*` variants are unused: Rust's default reallocation and
zeroing go through those two. A wrapper would not add a capability.
`PoolAlloc` returns memory Redis frees when the command returns, which needs a
lifetime tied to the command's `Context`. `MallocSize` and `MallocUsableSize`
are `unsafe` helpers in `alloc`, since they take raw pointers;
`RedisString::malloc_size` is the safe form for strings.

### Commands and replies

Missing: `CreateSubcommand`, the flag-carrying key and channel position APIs
(`KeyAtPosWithFlags`, `IsChannelsPositionRequest`, `ChannelAtPosWithFlags`),
and `RedactClientCommandArgument`. Subcommands fit registration; the others
fit command, next to `Context::key_at_pos`.

Replies cover the RESP2 and RESP3 types through `RedisValue`. Missing are RESP3
attributes (`ReplyWithAttribute`, `ReplySetAttributeLength`), postponed
aggregate lengths (`ReplySet*Length`, which #55 discusses as streaming replies)
and `ReplyWithNullArray`. Several others have an equivalent `RedisValue`, which
the table names. `ReplySetPushLength` is in the header but in no examined Redis
source; it came into the header with upstream PR 253 (`70960fc`).

The generated list of APIs required above the lowest floor is for review, not a
list of defects. The `CallReply*` accessors on it read RESP3 reply types, which a
call cannot produce on Redis 6. Replying with `RedisValue::Bool`, `BigNumber` or
`VerbatimString`, and calling `Context::get_current_user`, used to panic on a
Redis 6 server (#109). The replies now fall back to what Redis 6 can send, and
`get_current_user` looks the user up by client ID on Redis 6.2 and returns
`None` on Redis 6.0.

### Calls and strings

Call replies lack RESP3 attributes (`CallReplyAttribute`,
`CallReplyAttributeElement`). The string gaps are conversions Rust does itself
(`CreateStringFromLongLong` and the like) and the memory helpers
`TrimStringAllocation` and `HoldString`. Rust has no `long double`, and the
header comments out the five long-double functions, so they have no binding.

### Keys

These fit `RedisKey` or `RedisKeyWritable` and need no new context
capability: `ValueLength`, `GetExpire`, `GetAbsExpire`, `SetAbsExpire`, the
LRU and LFU functions, `GetKeyNameFromModuleKey` and `GetDbIdFromModuleKey`.
`KeyExists`, `RandomKey` and `ResetDataset` take no key and fit runtime.
`SignalModifiedKey` fits runtime and matters to a module that sets
`ModuleOptions::NO_IMPLICIT_SIGNAL_MODIFIED`, which the SDK exposes: such a
module has no safe way to signal a change. `RedisKey::to_raw_parts` gives
`unsafe` code the key pointer for any of these.

### Lists, hashes, sorted sets and streams

Lists have push and pop; `ListGet`, `ListSet`, `ListInsert` and `ListDelete`
(7.0) are missing. Hashes lack `HashFieldMinExpire` (8.0). No sorted-set API is
wrapped. Streams have iteration and `StreamTrimByID`; `StreamAdd`,
`StreamDelete`, `StreamIteratorDelete`, `StreamTrimByLength` and the stream ID
string conversions are missing. The key operations fit `RedisKey` or
`RedisKeyWritable`; the stream ID conversions are context-free.

### Native data types

`RedisType` registers a type, and `RedisModuleIO` has safe reads and writes.
The type callbacks in `RedisModuleTypeMethods` are still native
`extern "C"` functions, so reaching `RedisModuleIO` takes
`unsafe RedisModuleIO::new`. Missing: `ModuleTypeReplaceValue` (key),
`EmitAOF` and the I/O context accessors `GetContextFromIO`, `GetKeyNameFromIO`
and `GetDbIdFromIO` (callback), digest support, the key-options accessors that
the version 2 callbacks receive, and the string serialization functions
`LoadDataTypeFromString`, `LoadDataTypeFromStringEncver` and
`SaveDataTypeToString` (runtime). `SaveString` is reachable only through the
`unsafe` `raw::save_redis_string`, and `LogIOError` only through the `unsafe`
`logging::log_io_error`.

### RDB files

`RdbStreamCreateFromFile`, `RdbStreamFree`, `RdbLoad` and `RdbSave` (7.2) let a
module save the dataset to an RDB file, or clear it and load one. A wrapper
fits runtime.

### Clients, Pub/Sub and diagnostics

No wrapper returns a client's id, name, information or TLS certificate, or the
user name of a client other than the caller. `GetClientId` and
`GetClientInfoById` serve internal checks, and on Redis 6.2 `GetClientId` with
`GetClientUserNameById` gives `Context::get_current_user` the caller's user.
The client's own id fits command; lookups by id fit runtime. `PublishMessage`
and `PublishMessageShard` fit runtime; `PUBLISH` through `call` is the current
path. `LatencyAddSample` is context-free.

### Time and randomness

`milliseconds` is the only clock. `std::time` covers `Microseconds` and
`MonotonicMicroseconds`. `CachedMicroseconds` returns the time Redis caches
before each command and in its cron job, so that nested callbacks see one
clock; it has no Rust equivalent. `GetRandomBytes` and `GetRandomHexChars` are
context-free and ranked above.

### Dictionaries

None of the 22 dictionary functions is wrapped, nor `MallocSizeDict` or
`DefragRedisModuleDict`, which take a dictionary. With `RedisAlloc` as the
global allocator, Rust maps already count toward Redis's memory, so a wrapper
would mainly add Redis's radix tree with ordered iteration over byte keys. The
functions are context-free.

### INFO, server information and events

`InfoAddFieldCString` has the string path as its equivalent. The typed
`ServerInfoGetField*` getters are missing; `ServerInfo::field` returns the
string. `IsSubEventSupported` is missing. The server events without a handler
are persistence, client change, replica change, master link change, loading
progress, fork child, asynchronous replication load, event loop, key, the two
cluster slot migration events and the cluster topology change event (8.10).
Each would be a handler list like the existing ones.

### Keyspace notifications

`UnsubscribeFromKeyspaceEvents` (8.2) fits event. The subkey notification
APIs are unwrapped: `SubscribeToKeyspaceEventsWithSubkeys` and
`UnsubscribeFromKeyspaceEventsWithSubkeys` (8.8) fit event, and
`NotifyKeyspaceEventWithSubkeys` (8.8) fits runtime. So is the per-key
`AddPostNotificationJobForKey` (8.10), which fits event. `NotifyEvent` lacks the
`OVERWRITTEN`, `TYPE_CHANGED`, `KEY_TRIMMED`, `RATE_LIMIT`, `ARRAY` and four
subkey flags the header defines; the event handler drops bits it does not
know.

### Blocked clients

Missing: blocking on keys (`BlockClientOnKeys`, `BlockClientOnKeysWithFlags`,
`SignalKeyAsReady`, `GetBlockedClientReadyKey`), `GetBlockedClientHandle`,
`BlockedClientDisconnected`, `SetDisconnectCallback`, `AbortBlock`,
`BlockClientGetPrivateData` and the time measurement functions. Blocking fits
command; the handle functions fit the `BlockedClient`; `SignalKeyAsReady` fits
runtime.

### Thread-safe contexts

No gaps. `ThreadSafeContext::try_lock` and `DetachedContext::try_lock` wrap
`ThreadSafeContextTryLock` with the same guards as their blocking `lock`
methods (#113).

### Event loop

`event_loop::add` and `event_loop::remove` are `unsafe`: the caller must be on
the main thread and own the descriptor. `add_one_shot` is safe.

### Cluster

Nothing is wrapped. `cluster::key_slot` computes `ClusterKeySlot` in Rust on
every version. Message receivers and `SetClusterFlags` fit registration;
sending messages, node information, the slot functions added in 8.4 and
`GetClusterNodeSlotRanges` (8.10) fit runtime; `GetMyClusterID`,
`GetClusterSize` and `ClusterCanAccessKeysInSlot` are context-free.

### Shared APIs, command filters and fork

`ExportSharedAPI` is the `unsafe` `raw::export_shared_api`; `GetSharedAPI` is
missing. Both pass untyped pointers between modules, so a wrapper stays
`unsafe` or needs a typed protocol. A command filter runs in a filter context
that Redis describes as more limited than a module context: no `Call`, no
`OpenKey`. Registration fits registration, and the callback would need its
own view, as INFO callbacks have `InfoContext`. `Fork` and its child
functions have no request.

### ACL, users and authentication

`scoped_call_user`, the ACL checks for commands, keys and channels, and
`acl_add_log_entry` by user name are safe. Missing: creating module users and
setting their ACLs (context-free), authenticating or deauthenticating a
client (command and runtime), `RegisterAuthCallback` (registration) with
`BlockClientOnAuth` (callback), `ACLCheckKeyPrefixPermissions` (8.0),
`ACLAddLogEntry` with a user object, `GetUserUsername` (8.8) and
`GetInternalSecret` (8.0).

### Defragmentation

Missing: `RegisterDefragFunc2`, `DefragAllocRaw`, `DefragFreeRaw`,
`DefragRedisModuleDict` and the defragmentation context's key and database
accessors. All fit the callback. `DefragContext::defrag_realloc` is `unsafe`.

### Configuration

Module configurations are covered except `LoadDefaultConfigs` (8.0). The
server configuration APIs (8.2) are unwrapped; #60 evaluates read
helpers and `CONFIG GET` through `call` is the current path.

### Key metadata and Enterprise extensions

The key metadata class APIs (8.6) are unwrapped; classes fit
registration and values fit key. The Enterprise extensions came into the
header with upstream PRs 451, 478 and 486, without Rust wrappers; they have no
Redis OSS implementation to test against.

### Hand classifications

- `Alloc`, internal: `RedisAlloc`, the global allocator, and the allocator check
  in `redis_module!` use it; no wrapper allocates through it.
- `Free`, internal: `RedisAlloc` frees with it, and wrappers free buffers Redis
  returned (`RedisBuffer`, the key array of `get_command_keys`); no wrapper
  frees through it.
- `GetApi`, internal: the header's inline `RedisModule_InitAPI`, exported by
  `src/redismodule.c`, resolves every API pointer through it.
- `SetModuleAttribs`, internal: the header's inline `RedisModule_Init`, which
  `redis_module!` calls through `src/redismodule.c`, calls it.
- `IsModuleNameBusy`, internal: the header's inline `RedisModule_Init`, which
  `redis_module!` calls through `src/redismodule.c`, calls it.
- `GetClientId`, internal: `Context::acl_add_log_entry` and the blocking checks
  behind `block_client` and `block_client_on_reply` only test that the context
  has a client, and `Context::get_current_user` passes the id to
  `GetClientUserNameById` on Redis 6.2; no wrapper returns the id.
- `GetClientInfoById`, internal: `Context::block_client` only checks, before
  Redis 6.2, that the client is in the client index; no wrapper returns client
  data.
- `GetContextUser`, internal: `RuntimeContext::scoped_call_user` reads it to
  restore the outer user later; no wrapper returns the context user.
